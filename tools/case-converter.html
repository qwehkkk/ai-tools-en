About naming conventions

Which convention should I use?

It depends on the language and the file. JavaScript and Java use camelCase for variables and PascalCase for classes; Python and Ruby prefer snake_case; CSS classes, URLs and npm package names conventionally use kebab-case; constants are usually CONSTANT_CASE. Follow the style guide of the codebase you are in before anything else.

How is the text split into words?

First on separators such as spaces, underscores and hyphens, then on case boundaries: getToolkit becomes get and Toolkit, and XMLHttpRequest becomes XML, Http and Request. Numbers stay attached to the word they touch, so sha256Hash splits into sha256 and Hash rather than falling apart.

Why did my acronym change shape?

Each output applies its own capitalisation rules, so an acronym like ID comes out as Id in PascalCase and id in camelCase. That matches how most converters behave and how identifiers are usually written, but if you need the original casing preserved in a specific spot, edit the pasted result.

What about non-English text?

The word splitter works on ASCII letters and digits. Text in other scripts is passed through mostly unchanged into the spaced variants, but the camel and snake forms will not be meaningful — those conventions assume Latin script.

Is my text uploaded anywhere?

No. The conversion runs entirely in your browser with JavaScript. Nothing leaves your device.
